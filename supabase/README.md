# Supabase for SAULI

Facebook sign-in continues to use Supabase Auth's managed user records. The [initial application migration](migrations/202610080001_sauli_initial_schema.sql) creates found-item and search tables. The [storage-slot migration](migrations/202610110001_sauli_storage_slots.sql) adds 15 positions and atomic placement. The [retrieval migration](migrations/202610110002_sauli_retrieval_sessions.sql) adds hashed one-time QR sessions, retrieval events and logs, and atomic issue, validation, replacement, and completion functions. The [live-status migration](migrations/202610110003_sauli_retrieval_live_status.sql) lets the claimant see the validated position and wrong-item state after kiosk scanning.

The [email-notification migration](migrations/202610120001_sauli_email_notifications.sql) adds missing reports, durable matching jobs, an EmailJS outbox, and a database dispatch clock. It updates the placement function to enqueue matching only when a slot becomes occupied, and updates match decisions so accepting marks the report matched while rejecting leaves it active. No EmailJS credentials are stored in Supabase.

Migrations are not applied automatically. After linking the correct project and reviewing its migration history, run `supabase db push --dry-run` and then `supabase db push` from the repository root. If earlier migrations were applied manually outside CLI history, reconcile that history before pushing; alternatively apply only the unapplied SQL files in order through the Supabase SQL Editor. Never run `supabase db reset --linked` against this project. Setup and verification queries are in [services/README.md](../services/README.md).

For an intentional development data wipe, first empty the `sauli-item-images` bucket through the Supabase Storage dashboard or API, then run [reset_sauli_data.sql](reset_sauli_data.sql) manually in the SQL Editor. The script removes found items, searches, match candidates, missing reports, matching jobs, email notifications, slot events, retrieval sessions, retrieval events, and retrieval logs, and returns all 15 seeded positions to `available`. It preserves Auth users (including the admin account), the bucket, and the schema. It is **not** a migration and must never be applied with `db push`. Update the reset script whenever the application schema or storage layout changes.
